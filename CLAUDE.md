# Double Holy Cards for Tainted Lost

Mod for The Binding of Isaac: Repentance+. Vanilla Lua API only, no REPENTOGON unless stated otherwise.

## What the mod does
For Tainted Lost, a randomly rolled card gets an extra roll to become a Holy Card, slightly improving
survival. Target: 20% combined with vanilla's own roll, i.e. twice vanilla.
- Vanilla's roll is exactly 10% (`RandomInt(10) == 0`), confirmed in REPENTOGON's reimplementation of
  `ItemPool::GetCardEx` (`repentogon/Patches/CardsExtras.cpp`). It fires when any player is Tainted
  Lost, applies to every card type including runes and objects, needs no unlock, and is skipped
  when the roll does not allow special cards (`specialChance` zero).
- Hooked on `MC_GET_CARD`, which fires only when the game rolls a random card.
- Affected: room drops, chests, shops (the card stays paid), items that roll cards (Deck of Cards,
  Booster Pack, ...).
- Unaffected: cards dropped from the inventory and scripted spawns with a fixed subtype
  (e.g. The Fool on Depths II and its alternates).
- Verified in game on 2026-10-21 with `HOLY_CARD_CHANCE = 1`: all of the above, plus no effect for
  other characters.
- Measured 2026-10-21 with `HOLY_CARD_CHANCE = 1 / 9`: 39/203 = 19.2% Holy Cards overall from
  `spawn 5.300.0` (expected ~18.9% with 11% runes/objects that keep vanilla's 10%), 95% CI
  13.8-24.6%. Vanilla-only 10% and a stacked 28% are both ruled out.
- Replaced card types: tarot, reversed tarot, playing cards, special cards. Runes, soul stones and
  special objects (Dice Shard, Cracked Key, ...) stay as rolled.
- Known gap: `MC_GET_CARD` does not expose `specialChance`, so the mod may give a Holy Card in a roll
  where vanilla deliberately excludes special cards. Accepted; revisit only if a test shows it.

## Environment
- Lua 5.3, Windows, VS Code with `sumneko.lua` and `Filloax.isaac-lua-api-vscode`.
- No build step. The code cannot be run from the CLI, gameplay is tested only in the game. Never
  guess results, ask for the log to be pasted.
- CI (`.github/workflows/ci.yml`): `lua-language-server --check` against the vanilla API definitions,
  plus `.github/scripts/check_mod.py`, which fails on a `<name>`/`RegisterMod` mismatch or on test
  values (`DEBUG = true`, `HOLY_CARD_CHANCE = 1`) left in `main.lua`. Run it locally with
  `python .github/scripts/check_mod.py`.
- The repo is linked by a junction as
  `steamapps\common\The Binding of Isaac Rebirth\mods\tlost-double-hc`.
- `.luarc.json` is generated by the Isaac extension (gitignored, machine-specific paths).
  `.vscode/settings.json` sets `boi-lua.repentogonEnabled: false`, so it loads the vanilla stubs;
  REPENTOGON-only globals were removed from its `diagnostics.globals` by hand and may come back
  when the extension regenerates the file.
- Isaac writes to `%USERPROFILE%\Documents` even when Documents is redirected to OneDrive.

## Test loop (in-game console, `~`)
- `luamod tlost-double-hc` - reload the mod without restarting the game.
- `restart 31` - new run as Tainted Lost (`restart <PlayerType id>` in general).
- `spawn 5.300.0` - random card.
- `spawn 5.100.0` - random collectible pedestal from the room's pool.
- To test exclusions, temporarily set `HOLY_CARD_CHANCE = 1` and `DEBUG = true`: every card that
  reaches the callback turns into a Holy Card and gets logged.
- Logging: `Isaac.DebugString("[TLOST_DOUBLE_HC] ...")` writes to
  `Documents\My Games\Binding of Isaac Repentance+\log.txt`. The VS Code task `Isaac: tail log`
  follows it, filtered to `TLOST_DOUBLE_HC|Error`.

## Code rules
- API docs: https://wofsauge.github.io/IsaacDocs/rep/ - check signatures, never invent methods.
- Everything in `main.lua` until it exceeds ~200 lines, then split with `include("scripts.<name>")`.
- Config constants at the top of the file, `DEBUG` flag gates logging.
- A callback that calls an API firing the same callback (e.g. `ItemPool:GetCard` inside
  `MC_GET_CARD`) needs a recursion guard and `pcall`, so the guard always resets.
- Randomness only from a game-seeded RNG, never `math.random`, to keep seeds deterministic.
- `RNG:SetSeed`: seed never 0 (`math.max(seed, 1)`), shift index 35.
- Never touch items tagged `ItemConfig.TAG_QUEST`.
- Never edit the `<id>` field in `metadata.xml`, the Workshop uploader assigns it.
- Versions: GitHub releases (`release.yml`) set `<version>` in the repo. ModUploader bumps the last number
  on every upload (0.1.0 became 0.1.1 on the Workshop), and that bump is accepted: the Workshop version
  runs ahead of the repo by its patch number, so it is not synced back into the repo.
